# 设计决策（design-decisions.md）

## D1: fork 死项目而非自研

**决策**：fork 已弃用的 new-tab-default-page 二次开发，不自己从零写。

**理由**：目标功能完全匹配（新 tab 打开指定笔记），代码仅 240 行 TS，零 runtime 依赖；已有两年社区验证的行为细节（空 tab 检测、兼容模式）自研要重新踩坑。

**不选 B 的原因**：自研需重新处理 layout-change 时序、与其他开新 tab 插件的冲突，成本高于改造。

**何时重新考虑**：若上游 API 大改导致 fork 无法工作，或功能需求偏离原插件模式过远。

## D2: 本地优先，删除原作者发布基建

**决策**：删除 GitHub CI 发布工作流、`.release.mjs`、Justfile、lint 工具链，只保留构建核心。

**理由**：本地开发闭环（bump → build → deploy → reload）足够，不面向社区市场发布；原作者的 macOS 工作流在 Windows 无用。

**不选 B 的原因**：保留会引入无用依赖和过时配置；将来要发布时按需重建 CI 比维护死代码成本低。

**何时重新考虑**：决定发布到 Obsidian 社区市场时，重建 release workflow。

## D3: 一条龙重载模式（默认重载）

**决策**：deploy 默认执行 disable/enable 重载（一条龙），`-NoReload` 可跳过。

**理由**：插件无运行状态（配置在 data.json），重载不丢数据，可安全自动重载。

**不选 B 的原因**：重载可选模式每次发布多一步人工操作，对无状态插件不必要。

**何时重新考虑**：若未来加入运行状态（如内存缓存、连接），须回到重载可选模式——每个新插件项目重新确认此决策。

## D4: i18n 用类型安全字典 + auto 语言检测

**决策**：独立 `i18n.ts` 定义 `Dict` 接口 + zh/en 实现，设置加 `language` 字段（auto/zh/en），默认 auto 跟随 Obsidian UI 语言（`moment.locale()`），切换立即重绘设置面板。

**理由**：类型安全（缺翻译编译报错）保证双语同步；auto 模式对用户零配置。

**不选 B 的原因**：用现成 i18n 库（如 i18next）对 4 个设置项过度；简单 map 无类型约束会漏键。

**何时重新考虑**：翻译键超过 50 个或需支持 3+ 语言时，升级为正式 i18n 库。

## D5: 版本号延续原项目而非重置

**决策**：保留原项目版本号基线（fork 时 0.11.9），通过 bump-version.mjs 递增，不重置为 0.1.0。

**理由**：版本号唯一作用是追踪"当前运行的是哪版代码"，延续基线 + 递增语义（patch/minor/major）已满足，重置无收益。

**不选 B 的原因**：重置 0.1.0 会丢失与原项目的版本对应关系，且需手动处理 versions.json 历史。

**何时重新考虑**：正式对外发布到社区市场时，可考虑语义化重置。
